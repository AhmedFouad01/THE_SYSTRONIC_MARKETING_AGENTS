# TSST-LENS-SK-011 Copywriting

Status: `UNVALIDATED`

## Objective

Turn an approved message house into clear, specific, on-brand copy that earns the next action, with every material claim attached to proof and a testable set of variants.

## Triggers

Use for ad copy, social posts and captions, landing-page sections, CTAs, product descriptions, email subject lines, and copy reviews or rewrites. Not for positioning (SK-005), Arabic/Egyptian register work (SK-012; use it alongside this skill for AR copy), or visual design (STUDIO).

## Reusable principles

- Copy executes a message hierarchy; it does not invent one. No message house, no copy: return the gap.
- One piece, one audience, one job, one CTA.
- Lead with the reader's situation or desired outcome, not the brand.
- Specific beats superlative: a number, a named outcome, or a concrete detail over "best", "premium", "revolutionary".
- Every claim carries proof or a qualifier (inherits SK-005 claim discipline and SK-002 evidence grading). Unproven means hypothetical or cut.
- Answer the likely objection near the claim that triggers it.
- Plain words, short sentences, active verbs; read it aloud.

## Workflow

1. Brief intake. Confirm: brand, audience segment, offer, single goal, funnel stage, platform and format, tone, mandatory/forbidden words, proof available, legal/compliance constraints, language(s). Missing items: ask once, then state assumptions.
2. Pull from the message house: core promise, the one pillar this piece serves, its proof, and the top objection.
3. Choose the angle: pain, outcome, curiosity, social proof, contrast with the alternative, or urgency (only if real).
4. Write hooks first: 8-10 options across frameworks (table below); pick 3 that differ in angle, not wording.
5. Draft body: situation, value (capability linked to outcome), proof, objection answer, CTA. Cut anything that does not serve the one job.
6. Attach proof: quote, number, case, guarantee, or process fact, each with its source reference. Qualify scope ("in our 2025 customer survey", "for orders over X").
7. Write the CTA: verb + what happens next + low-friction framing ("See the range", "Get a quote in 2 minutes" only if true).
8. Variants for testing: change ONE variable per test (hook, proof type, CTA, or length). Name each variant, state the hypothesis and the metric that decides it. Hand test design and spend to SPARK_AG.
9. QA pass (gates below). Revise, then package.

### Hook / headline frameworks

| Framework | Pattern | Use when |
|---|---|---|
| Problem-agitate | Name the pain in the reader's words | Pain is felt and known |
| Outcome-first | Result + timeframe/condition | Outcome is provable |
| Contrast | "X, without Y" / old way vs new way | Clear alternative exists |
| Specific number | Concrete figure + context | A verified number exists |
| Question | One question the reader answers "yes" to | Early funnel, low claim load |
| Social proof | Quote or count + who | Real, permissioned proof exists |
| Curiosity gap | Open a loop the body closes | Never mislead; body must pay off |
| Direct offer | What, for whom, how to get it | Bottom funnel |

### Platform length reference (verify before use)

Limits change often and differ by placement and language. Treat every figure as a working default and check the current official platform documentation before locking copy.

| Placement | Working default | Status |
|---|---|---|
| Meta ad primary text | ~125 chars visible before truncation | verify before use |
| Meta ad headline | ~40 chars | verify before use |
| Instagram caption | up to ~2,200 chars; first ~125 visible | verify before use |
| TikTok caption | ~2,200 chars (limit has changed over time) | verify before use |
| LinkedIn post | ~3,000 chars; first ~210 visible | verify before use |
| Google RSA headline / description | 30 / 90 chars | verify before use |
| Email subject | ~40-50 chars to avoid mobile cut | verify before use |

Arabic text may truncate at different points than Latin; preview in the real placement.

## Output contract

- brief summary and stated assumptions;
- hook shortlist (3) with framework named;
- final copy per placement, within verified length;
- proof map: claim -> proof source -> qualifier;
- objection handled and where;
- test plan: variants, single variable, hypothesis, deciding metric;
- QA result and open items for native review, STUDIO, or compliance.

## Quality gates / critical failures

Pass all gates; any critical failure blocks delivery.

- [ ] CRITICAL: no unproven or unqualified material claim (superlatives, guarantees, percentages, "first/only", health/financial outcomes).
- [ ] CRITICAL: no invented testimonial, statistic, price, scarcity, or deadline.
- [ ] CRITICAL: copy matches the offer's real terms (price, availability, conditions).
- [ ] One audience, one job, one CTA.
- [ ] Hook works without the image; first line stands alone where truncated.
- [ ] Readability: short sentences, no jargon the audience would not use, no filler.
- [ ] Tone matches brand voice rules supplied in the brief.
- [ ] Platform policy risk checked (restricted claims, before/after, personal attributes) against current official policy.
- [ ] Variants differ by one variable.
- [ ] Arabic copy routed to SK-012 and native review.

## Handoffs

- Positioning/message gaps -> SK-005. Evidence questions -> SK-002.
- Arabic or Egyptian copy -> SK-012 (register, transcreation, native review).
- Visual execution, layout, text-on-image -> STUDIO via the SK-013 brief format.
- Test setup, budget, tracking -> SPARK_AG. Final visual approval -> CREATIVE_AG.
- No publishing; copy is delivered as draft for approval.

## Common failure modes

- slogan-first copy with no proof;
- feature lists instead of outcomes;
- several CTAs competing;
- manufactured urgency;
- copying competitor phrasing the audience already ignores;
- testing many variables at once, so nothing is learned.
