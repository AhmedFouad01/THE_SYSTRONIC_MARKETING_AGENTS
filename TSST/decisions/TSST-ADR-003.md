# TSST-ADR-003 — Permanent team-agent roster, central skill index, enforced Skill Plan

Date: 2026-10-05. Decision owner: user. Integration owner: TSST Lead.
Status: APPROVED — runtime roster mapping, skill index, dispatch enforcement, skill intake.

## Authority
User instruction in chat (Arabic, 2026-10-05), summarised: the work on TSST must be done by
TSST's own agents with their skills — never temporary/ad-hoc agents; the agents are fixed and
the *skills* evolve; all skills live in one place and are called on demand to save tokens; the
Lead (main conversation) decides which skills a task needs, recommends them, may scout the
cleanest available skills, then assigns them to the team member; strict rules. The user
approved the Lead's design report with "تمام كمل".

Open choices taken at the Lead's recommended default (user may reverse):
index-first (no physical move of skill folders) · scouting sources = installed
skills/plugins + Anthropic sources; any download needs per-item user approval · P1 skills
authored brand-neutral (no brand selected yet).

## Problem (evidence: Lead report 2026-10-05)
1. Claude runtime workers were model tiers (`tsst-execution-worker`, `tsst-code-worker`), not
   TSST agents — LENS/SPARK/CREATIVE/DEV existed only as documents.
2. 109 skill packages in 6 folders, no single compact index; CTX skills lacked frontmatter.
3. Marketing had no skills for copywriting, Arabic copy, organic social, CRO/landing pages,
   WhatsApp/email lifecycle (+11 registered backlog skills).
4. Bus checked skill *file existence* only; in-chat subagent dispatch was not checked at all.
5. No intake procedure for new/external skills.

## Decision
1. **Roster (fixed).** Claude subagents now *are* the TSST agents: `tsst-lens` (LENS_AG),
   `tsst-spark` (SPARK_AG), `tsst-creative` (CREATIVE_AG + DESIGNER/MOTION), `tsst-dev`
   (DEV_AG). Lead stays in the main conversation (DEEP). `tsst-fast-worker` and `Explore`
   remain **utility readers** only. `tsst-execution-worker` and `tsst-code-worker` are retired.
   Adding/removing an agent requires a new ADR.
2. **One skill entry point.** `TSST/skills/index.yaml` (generated by
   `TSST/skills/build_index.py`) lists every skill: id, team, owner, status, version, trigger,
   path. Lead reads only the needed team slice; agents load ≤3 `SKILL.md` by path. Skills are
   not registered as runtime-native skills (avoids per-session metadata cost; stays portable).
   New skills go to `TSST/skills/<team>/<slug>/`. Physical consolidation of existing folders
   is a later, separate decision.
3. **Skill Plan before every dispatch** (TEAM / AGENT / SKILLS / NOT_SELECTED / TIER /
   ACCEPTANCE / SKILL_GAP). Enforced in code: Claude PreToolUse hook
   `TSST/context/hooks/agent_dispatch_guard.py`; bus `team_skill_errors` validates against the
   index (exists, not DEPRECATED, team match).
4. **Skill intake** `TSST-CTX-SK-023`: gap → scout (domain owner) → compare (Lead) → user
   approval for anything external → adapt to TSST format → index → evaluate (CTX-SK-018).
5. **Evolution.** Agents return `skill_friction`; Lead versions skills; promotion only via
   CTX-SK-018 evidence. Rules R1–R10 added to `TSST/core/rules.md`.

## Limits
No readiness change: all agents remain NOT_READY; new skills start UNVALIDATED. No
publication, spend, client contact, or download granted. Existing registries, evaluations
and Real Memory are unchanged; skill folders are not moved.
