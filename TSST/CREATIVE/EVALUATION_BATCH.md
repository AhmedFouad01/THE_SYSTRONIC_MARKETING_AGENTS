# CREATIVE Integrated Evaluation Batch

Purpose: validate multiple production skills economically using rendered evidence. Do not auto-promote all mapped skills from one good-looking output.

## Batch A — Social Key Visual System

Maps primarily to: SK-004, SK-005, SK-006, SK-008, SK-011, SK-012, SK-013, SK-014, SK-010, SK-019.

Task: fictional bilingual consumer brand. Create three visually distinct KV directions, select one, then render:
- 1080×1350 hero feed post;
- 1080×1920 Story adaptation;
- four-card carousel with meaningful visual variation.

Minimum pass: 85/100 overall; hierarchy, originality, production realism and mobile readability each ≥12/15. Actual renders mandatory.

## Batch B — Motion Reveal

Maps primarily to: SK-008, SK-015, SK-016, SK-017, SK-018, SK-019, SK-010.

Task: create a 12–18 second bilingual brand reveal from supplied still/video assets. Deliver actual rendered MP4/MOV when rendering tools are available plus 4 QA frames.

Score: hook, edit structure, motion craft, typography readability, sound, color continuity, brand fit, export QA.

## Batch C — Performance Variant System

Maps primarily to: SK-009, SK-011, SK-012, SK-016 and SPARK handoff quality.

Task: one approved message → four hypotheses. Render two still/short variants that differ by a controlled meaningful variable; supply hypothesis/test map and no unsupported performance claims.

## Batch D — Visual Red Team / QA

Maps primarily to: SK-010 and SK-019, with typography/color/layout evidence.

Task: review a 12-asset fixture containing obvious and subtle failures. Identify, prioritize, fix and re-inspect defects.

## Automatic failure conditions

- HTML/browser/brief presented as final social asset;
- repeated near-identical text-card templates used as the campaign solution;
- broken Arabic shaping/bidi;
- distorted logo/product or focal generative artifacts;
- requested professional video reduced to a slideshow/static-card motion without approved rationale;
- no rendered visual QA;
- fabricated claims, rights or platform-clearance statements.

## Validation policy

One batch may provide evidence for multiple skills, but each skill receives a separate evidence note and status decision. `VALIDATED` requires repeatable evidence; `LAB_VALIDATED` may be used for a bounded, high-quality lab execution with clearly stated production limits.
