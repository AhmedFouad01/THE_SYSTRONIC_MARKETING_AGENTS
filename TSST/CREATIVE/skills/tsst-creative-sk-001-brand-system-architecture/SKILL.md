# TSST-CREATIVE-SK-001 Brand System Architecture

Status: `VALIDATED` — passed `TSST-CREATIVE-EV-001` with 95/100.

## Objective

Turn an approved brand brief into a coherent system covering logo, color, typography, imagery, layout, motion, and explicit do/don't rules. A system must explain how decisions relate, not merely collect assets.

## Triggers

Use when asked to define, restructure, or audit a visual identity; create a brand-system specification; or translate brand strategy into repeatable cross-channel rules.

## Reusable principles

- Start from audience, context, brand attributes, and required behavior before choosing visual treatments.
- Define foundations first, then composition rules, applications, and exceptions.
- Give each element a role. A palette, typeface list, or logo folder without usage logic is not a system.
- Preserve hierarchy across expressive and functional contexts while adapting execution to the surface.
- Provide approved examples and prohibited treatments so the boundary is testable.
- Treat a reference brand guide as a documentation example, never as permission to reuse its identity or assets.

## Workflow

1. Confirm the brief, approved positioning, audiences, languages, channels, asset rights, accessibility requirements, and unknowns.
2. Inventory supplied brand assets and classify each as approved, provisional, obsolete, or missing.
3. Translate approved brand attributes into observable visual principles and anti-principles.
4. Define the logo system, color roles, typography roles, imagery, layout/grid, graphic elements, and motion behavior.
5. Specify how foundations combine in common surfaces and how rules adapt between expressive and functional work.
6. Add do/don't rules, minimum sizes, clear space, contrast, cropping, safe zones, and exceptions where evidence supports them.
7. Test representative social, deck, and web applications. Record defects and unresolved choices.
8. Run CREATIVE_AG visual QA and request LENS_AG review of strategic alignment.

## Output contract

- brief trace and declared unknowns;
- brand attributes translated into visual principles;
- foundation rules with rationale and ownership;
- cross-channel application matrix;
- do/don't rules and exceptions;
- asset inventory and rights status;
- QA checklist, test results, and open risks.

## Guardrails

- Do not copy GitHub's identity, layouts, illustrations, type treatments, or assets.
- Do not fabricate a logo, brand history, audience belief, or strategic attribute when the brief is silent.
- Do not let one moodboard or application become the entire system.
- Do not accept a system that lacks accessibility, localization, or production constraints relevant to its surfaces.

## Completion checklist

- [ ] Every visual rule traces to an approved strategic input or practical constraint.
- [ ] Each foundation has a defined role, usage rule, and prohibited treatment.
- [ ] Arabic/Latin and cross-channel behavior are addressed when applicable.
- [ ] Assets and rights are explicit.
- [ ] Representative applications were tested.
- [ ] CREATIVE_AG visual QA is recorded.

## Practical evaluation

Convert a supplied fictional brand brief into a clear brand system with guardrails. The fixture must include at least two audiences, Arabic and English copy, and social, deck, and web surfaces. Score with the team evaluation scorecard; any copied reference identity or invented brief fact is a critical failure.

## Common failure modes

- asset catalog with no decision logic;
- decorative rules unrelated to positioning;
- conflicting treatments across channels;
- vague instructions such as “use strong visuals”;
- missing forbidden treatments or exceptions;
- claiming compliance without application tests.
