## 3. Offer architecture وconversion journey

**RECOMMENDATION:** الشركة تقدم full interior design / fit-out كنطاق جامع. مسارات عرض مقترحة: design scope، execution/fit-out scope، integrated whole-home scope؛ كل quote يحدد ما يشمله وما يستثنيه، ownership، timeline، payment/change terms. توافر design-only تجاريًا OPEN، وليس خدمة مؤكدة.

**FACT — stored proposal:** three kitchen packages، 4–6 signature design families وmaterial matrix مقترحات قائمة، لا أسعار/خدمات معتمدة. [S2 §5] **RECOMMENDATION:** احتفظ بالـ3 packages كهيكل مبدئي للمقارنة، differentiated by documented material/spec/service choices؛ أسماءها وأسعارها وتوافرها تنتظر costing واعتماد operations. Estimate range لا يُعرض قبل قاعدة تسعير واقعية؛ عند غيابها، CTA = Project Assessment.

**RECOMMENDATION — kitchen paid entry:** الإعلان يتحدث عن احتياج مطبخ محدد → kitchen page → assessment → measurement → kitchen proposal. الصفحة تعرض whole-home capability كامتداد اختياري، دون تحويل رسالة الإعلان إلى وعد kitchen-only brand. Upgrade: سجّل احتياج الغرف الأخرى مبكرًا، ثم اقترح dressing/storage أو whole-home بعد موافقة العميل وcapacity review؛ لا تُحسب expansion كعميل جديد.

**RECOMMENDATION — journey:** Ad/Search/organic/referral → relevant service page → Project Assessment → qualification → estimate where supportable → confirmed site visit/measurement → 3D/proposal with scope → signed contract → deposit verification → execution → handover proof → review/referral/optional expansion. Signed value، collected cash وrecognized revenue ثلاث قيم مختلفة؛ لا نساوي بينها.

**RECOMMENDATION — sales handling:** intake fields = location، property/service type، area، budget band، handover date، desired timeline، contact preference؛ collect only needed data. Qualified = serviceability + feasible scope/timing + budget fit to a real estimate basis + decision contact + available delivery capacity. Unknown fields = Needs info، not automatically qualified. Sales owner assigns next action/date; proposed business-hours first-human-response SLA ≤30 minutes is a **HYPOTHESIS** to approve against staffing, not observed performance.

## 6. CRM،event map وmeasurement

**RECOMMENDATION — ownership:** Sales owns lead/opportunity stages؛ Operations validates serviceability/capacity/site/handover؛ Finance owns contract/cash/cost/profit reconciliation؛ SPARK owns measurement definitions/QA؛ Lead integrates weekly decisions. These are required roles to assign, not confirmed staff availability.

**RECOMMENDATION — stages:** New → Contacted → Needs info / Qualified → Visit scheduled → Visit completed → Proposal sent → Negotiation → Signed → Deposit received → In execution → Handed over. Lost/Disqualified have reason + timestamp؛ no answer remains pending before a defined follow-up policy. Store stage history; do not overwrite timestamps. Duplicate leads merge under one contact while distinct project opportunities remain separate.

| RECOMMENDATION: event | Exact business trigger / required keys | System of record and owner |
|---|---|---|
| service_view / assessment_start | relevant page viewed / assessment begins؛ session_id, service, geo bucket | Web analytics / SPARK؛ secondary only |
| lead_created | Valid submission accepted or manual inquiry saved؛ lead_id, event_id, source/UTM when available, created_at | CRM / Sales؛ distinguish from click-to-message |
| lead_qualified | Sales completes qualification rule؛ lead_id, opportunity_id, service, geo, reason, occurred_at | CRM / Sales + Operations |
| visit_completed | Actual completed measurement/site visit؛ opportunity_id, visit_id, occurred_at | CRM / Sales + Operations |
| proposal_sent | Quote delivered؛ opportunity_id, proposal_id, revision, EGP value, sent_at | CRM / Sales؛ active revision only in pipeline |
| contract_signed | Executed contract verified؛ opportunity_id, contract_id, signed_value, currency, signed_at | Contract register / Finance |
| deposit_received | Cleared payment confirmed؛ contract_id, payment_id, amount, received_at | Finance؛ not a second new-project conversion |
| project_handed_over / expansion_opened | Accepted handover / separate scoped expansion inquiry؛ project_id, acceptance_id or new opportunity_id | Operations / Sales |

**RECOMMENDATION — identity & QA:** event_id stable per underlying action across retries/browser/server; lead_id for person inquiry، opportunity_id for project، contract_id/payment_id for commercial records. CRM wins for stage counts، Finance for cash/cost، platform attribution remains a separate view. Consent-denied paths suppress nonessential marketing tracking; data policy/retention and upload permission must be assigned before implementation. No contact details in UTMs/event parameters. Platform mappings/offline import configuration require later SPARK verification against current official docs.

**RECOMMENDATION — optimization:** lead_created is a provisional signal if qualified conversion volume/eligibility is insufficient؛ lead_qualified is the intended quality signal once reliable. Signed projects/GP remain business decisions؛ do not sum leads، qualifications and wins as one conversion outcome. QA cases before launch: valid journey، invalid submission، duplicate/retry، consent denied، manual/referral lead، delayed win، revised proposal، cancellation/payment reversal and expansion. Reconcile counts by IDs and dates; unresolved missing/duplicate records block optimization changes.
