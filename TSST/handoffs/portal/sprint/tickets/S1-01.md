## Facts worth keeping (from `scripts/deploy.sh`)
- A deploy keeps the release it replaced as `previous`; `--rollback` swaps `current` and `previous` and restarts.
  Running it twice returns to the newer release.
- Before migrating, a deploy writes `/srv/tsst/backups/pre-deploy-<release>.sql.gz` (the 10 newest are kept).
- Migrations only go forward. After a failed health check the script puts the old code back by itself, but the
  database keeps the migration.
- The server keeps the 5 newest releases, and never deletes `current` or `previous`.
