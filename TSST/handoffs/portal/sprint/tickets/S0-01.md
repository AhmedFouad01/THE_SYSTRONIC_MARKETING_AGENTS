# S0-01: add the missing SPA routes

Part S0 (hotfix). Gate: deploy. Depends on: nothing. Approved by Ahmed 2026-11-05 ("Start S0"); the deploy needs its own OK.
State lives on `../BOARD.md`; this file holds the scope, the acceptance list and the evidence.

## Problem
`web/src/App.tsx` declares pages that `src/server/spa.ts` `SPA_ROUTES` does not list. The server answers them with
404 JSON when they are opened directly or refreshed (a bookmark, a refresh, a link sent on WhatsApp). In-app navigation works,
so nobody saw it. The pinned list in `tests/spa.test.ts` asserts the same wrong list.

## Scope
Repo `~/Work/tsst-portal`, branch `sprint/s0-01-spa-routes` cut from `origin/main` (`6290115`) in its own worktree.

Add these 10 routes to `SPA_ROUTES` (checked against `App.tsx` at `6290115`; the plan named 5, the code has 10):
`/client/for-your-review` · `/client/review` · `/client/work` · `/client/posts` · `/client/videos` · `/client/designs` ·
`/client/requests` · `/client/request` · `/jobs/post` · `/clients/project`

Left out on purpose:
- `*`: the not-found page is not a route.
- `/c/:token`: the server's `clientLink` handles it before the SPA lookup.
- `/design`: mock-only page, not in a live build.

Files:
- `src/server/spa.ts`: the 10 routes.
- `tests/spa.test.ts`: the pinned list, plus a new guard test that reads `web/src/App.tsx`, takes every static
  `<Route path="...">` (no `:` or `*`, not `/design`) and fails when one is missing from `SPA_ROUTES`.
- `docs/DASH-API.md`: the "Front-end routes" section lists the same routes.

No other change. One route list for all three places is S2-01, not this ticket.

## Acceptance
1. Each of the 10 routes returns the app shell (200, `text/html`), not 404, on a direct open or refresh.
2. The pinned list in `tests/spa.test.ts` equals `SPA_ROUTES`.
3. The guard test fails when a static route of `App.tsx` is missing from `SPA_ROUTES`.
4. Unknown paths still return 404 and never the shell; `/c/<token>` behaviour is unchanged.
5. `docs/DASH-API.md` "Front-end routes" lists the same routes.
6. Nothing else changes: no UI, API, migration or dependency change.
7. Checks green: `npm ci`, root typecheck, lint, `npx vitest run --no-file-parallelism`.
