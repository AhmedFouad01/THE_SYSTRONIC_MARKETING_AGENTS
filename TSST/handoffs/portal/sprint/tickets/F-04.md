## What is true today (read in the code by two readers)
1. Client routes: Home, For your review, My work, Requests. `/client/plan` and `/client/project` redirect to Home
   (`web/src/App.tsx`). The nav has four links (`ClientShell.tsx:100-112`).
2. The client Home (`ClientHome.tsx`, the same file since PR #27) draws: the review list, the latest ready work, a
   package bar, a "current / next campaign" box (needs `viewer.sections.plan` and a campaign with timing now / next;
   it shows name, dates and counts, never the stage), and "Need something new?". It never reads `home.timeline`,
   `home.projects`, `home.upcoming_posts`, although the server sends them.
3. The server still builds the whole plan for the client: `GET /api/v1/client-view/plan` (404 unless the client's
   `show_plan` is on) returns `stages[{stage, campaigns[]}]`, `roadmap[]`, `next_milestone`, `today`
   (`src/server/v1/plan.ts:576`, type `MarketingPlan` in `web/src/api/types.ts:284`). Nothing was removed there.

   تفعيل العملاء ...), with `StageChips`; `ClientProjectCards` and `ds/Roadmap.tsx` `RoadmapMap` are in the code and
   mounted nowhere. The team's Plan tab (`ClientPlanTab.tsx`) draws the five-stage board ("Growth stages").
5. Weak spots on the same Home card: the package card can be drawn with a title and nothing under it; `pack.included`
   is read without a null check (the server sends null for a paused subscription); a failed plan request is silent.
6. The team's setting hint promises "Stage and campaign on the client Home"; the "Milestones" switch has no visible
   effect on any client page.
The old client plan page (before PR #27) is at `2d9c851:web/src/pages/client/ClientPlan.tsx` (PlanBoard,
PackageDetails, MyRequests) for reference; it is a reference, not a file to restore as it was.

## Fix
A. **A client page "Plan"** at `/client/plan` (the redirect goes), in the nav as the second link ("Plan" / "الخطة"),
   shown only when the client's "Marketing plan" switch is on (`viewer.sections.plan`); when it is off the link is
   not drawn and the route keeps redirecting to Home. Read-only for the client. From top to bottom:
   1. Title "Your marketing plan" and one sentence that says where we are ("We are in Activation: <campaign>"), from
      the campaign with timing `now`, else `next`.
   2. **The five stages** in their order (Acquisition, Activation, Revenue, Retention, Referral) with the client's
      stage names, the current stage marked "We are here". Under each stage its campaigns; **a campaign with two
      stages shows under both**. A campaign card: name, dates, a word for its timing (now / next / done), its
      milestones "n of m done" with a meter, the next milestone and its date; the card opens to list its milestones
      (done ones ticked). An empty stage is one quiet line. Desktop: five columns; phone: the stages stacked, no
      horizontal scroll, the current stage open, the others folded to a line with their count.
   3. **What is coming** (only when the "Milestones" switch is on, `viewer.sections.timeline`): the dated list of
      the plan's roadmap (milestones and accepted requests), next ones first, grouped by month, done ones behind a
      "Show past" control; overdue is not shouted at the client (a neutral "was due" word).
   4. Loading, error with retry, and an empty state ("The plan has no campaigns yet.").
   Reuse the team board's drawing where it fits (extract a shared read-only piece from `ClientPlanTab.tsx` rather
   than a second copy; the team tab must look and behave as it does now), `StageChips`, and the client dictionaries.
B. **Home**: the focus box shows the campaign's stage chips and a "View plan" link; a short "Coming up" list (the
   next three dated milestones from `home.timeline`) when the timeline switch is on, with a link to the plan page
   when the plan is on; the package card is not drawn when it would be empty; `included` null is guarded; a failed
   plan request shows a small error with retry in place of silence.
C. **Team wording**: the "Marketing plan" switch hint says what it does now ("The Plan page with the stages, and the
   campaign box on the client Home"); the "Milestones" hint says "The coming-up list on the client Home and Plan".
   English and Arabic.
D. No server change is expected. If the mapper proves a field is missing from the client plan answer (for example a
   campaign's milestones list or its second stage), add it to the existing read as an additive field with a server
   test; no new route, no migration, nothing a client should not see (internal notes, hidden campaigns, money).
E. Mock data: the client mock carries a plan with campaigns in at least three stages, one campaign with two stages,
   milestones done / next / past, so the vite mock shows the page.

Not in this ticket (recorded): the client's project page and job page of before PR #27; package details and requests
on the plan page (the Home and Requests pages have them); the team client page (first tab, posts list, milestone
editing: a separate ticket if Ahmed asks); turning the switch on for existing clients (Ahmed does it per client in
Settings › What the client sees; no production data is changed by the deploy); changing the default of the switch.
