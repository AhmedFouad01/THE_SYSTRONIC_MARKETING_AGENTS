# S2-01: one list of pages, `shared/routes.json`

Part S2 (foundation). Gate: none. Depends on: S1-03. Approved by Ahmed 2026-11-06.
State lives on `../BOARD.md`; this file holds the scope, the acceptance list and the evidence.

## Problem
The list of front-end pages was written by hand in four places: `web/src/App.tsx`, `SPA_ROUTES` in
`src/server/spa.ts`, a pinned copy in `tests/spa.test.ts` and `docs/DASH-API.md`. A page added to the app and forgotten
on the server is a 404 on refresh (S0-01 fixed the second time it reached the live site). Also three links inside the
app still used `/clients/view?...&view=packages`, a query form the client page stopped reading, so they opened the wrong tab.

## Scope
Repo `~/Work/tsst-portal`, branch `sprint/s2-01-routes`, worktree `~/Work/tsst-portal-s2-01`,
PR [#33](https://github.com/AhmedFouad01/tsst-portal/pull/33) into `next`.

- `shared/routes.json` (new): `pages` (the 34 exact paths), `appOnly` (`/design`, a mock build only), `queryRedirects`.
- `src/server/spa.ts` reads `pages`. Root `tsconfig.json` gets `resolveJsonModule`.
- `tests/spa.test.ts`: the pinned copy is gone; the list must be clean; `App.tsx` must declare exactly these pages,
  both ways; every page must be in the docs section; redirect rules must name real pages.
- `web/src/lib/routes.ts` (new) + `App.tsx`: an old link is replaced by its current form before a page renders.
  Today: `/clients/view?view=plan` → `?tab=work`; `?view=packages` and `?view=ready-to-bill` → `?tab=package`.
- `docs/DASH-API.md`: the Front-end routes section names the list file and the old links.

`App.tsx` keeps its `<Route>` tree (the layouts live there); the test is what keeps it equal to the list.
S3 adds its own old-link lines to `queryRedirects` when the client page tabs change.

## Acceptance
1. `shared/routes.json` holds `pages`, `appOnly`, `queryRedirects`.
2. The server reads `pages` and serves the same 34 paths as before; unknown paths are still 404.
3. A new page = one line in the list plus its `<Route>` in `App.tsx`.
4. A test fails when `App.tsx` and the list differ, either way, or when the list holds a path that is not exact.
5. Old links land on the right tab; other parameters and the fragment are kept; Back does not loop.
6. The docs section names the list; a test fails when a page is missing from it.
7. The deploy works the same way (`scripts/deploy.sh` unchanged; the list is a tracked file).
8. No other visible change; no API, migration or dependency change.
9. Checks green.
