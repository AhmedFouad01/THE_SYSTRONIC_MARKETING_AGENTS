## Design
- `src/service/dash/health.ts`: `HEALTH_WORDS = ["on_track", "waiting_on_client", "attention"]`,
  `healthOf(input): { word, waiting, reasons }` — a pure function of
  `{ today, waiting_on_client: { days }[], changes_requested: { days }[], overdue_milestones: number,
     payment_overdue: boolean, over_allowance: boolean }`:
  - `attention` when any holds: a client's "changes requested" older than 3 days (the team owes a version); an item
    waiting on the client for 7 days or more (stuck); an unpaid payment due before today; a milestone due before today
    not done; a package line used beyond what is included. `reasons` lists which (`changes_owed`, `stuck`,
    `payment_overdue`, `milestone_overdue`, `over_allowance`).
  - `waiting_on_client` when none holds and at least one item waits on the client; `waiting` = that count.
  - `on_track` otherwise (`waiting` = 0).
  The two thresholds (3 and 7 days) are the Lead's defaults, named in the docs; Ahmed may change them at the deploy gate.
- `clientHealth(env, world, brand, today, packages, milestones)` builds the input from what the clients route already
  has (items of the brand: waiting = `itemVisible(i) && (!i.client || i.client.status === "pending")`, days from
  `i.live?.sent_at ?? i.created_at`; changes = `i.client?.status === "changes_requested"`, days from `i.client.at`;
  `next_payment.due < today && !paid`; milestones `due < today && !done`; any usage line `used > included`).
- `GET /api/v1/clients` adds `health: { word, waiting, reasons }` to each `ClientSummary`. Nothing else reads it yet
  (S3-05 draws it). Web: `ClientSummary.health` typed; the mock computes it the same way from its state (so the cards
  show words in mock mode); `ClientDetail` loses the "Active client" chip and both copies lose the key.
- Tests: `tests/health.test.ts` (pure: each word, each reason, the thresholds at the edge, today's date excluded from
  "before today"); `tests/v1-clients-health.test.ts` (the route: a brand with nothing → `on_track` 0; an item sent →
  `waiting_on_client` 1; a client change 4 days old → `attention` with `changes_owed`; an overdue payment → `attention`
  with `payment_overdue`); one web test that the mock's clients carry `health`.
- Docs: one section in `DASH-API.md` (the field, the words, the rules, the two thresholds).
