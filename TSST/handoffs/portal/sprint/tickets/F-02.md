## Causes (each confirmed by a second reader in the code)
1. **Team: "No caption on this version."** The server stores a post item's captions as an array
   `[{platform, md}]` (`src/service/dash/jobs.ts:949`); the web helper `captionBlocks`
   (`web/src/lib/item-bulk.ts:48-62`) reads only an object `{platform: text}` (the legacy shape of migration 027), so
   it returns nothing for every post saved since.
2. **Client: no caption code at all.** `ClientReviewQueue.tsx:125-232` never reads `preview.captions`, although the
   server sends it (`job-model.ts:451-469`), per version too.
3. **The work is drawn as one cropped picture.** Both panels put `media[0]` in an `<img>` inside `.preview-box`
   (16:9, `object-fit: cover`, `styles/job-model.css:83-84`): a 4:5 post loses 55% of its height, a 9:16 one 68%;
   carousels cannot be paged; a video or PDF first media is a broken image. No platform, format or ratio is shown.
4. **The picture is not the version under review.** Media loads through `/file`: for the team that is the file on disk
   now (an older version pill shows the new picture with the old caption); for the client it is the snapshot of the
   LIVE version, so a re-review after an approval shows the old picture (`src/server/app.ts:354-358`,
   `client-view.ts:205-207`). The routes for a version's own bytes exist and have no web caller:
   `GET items/:id/versions/:n/file?path=` and `GET client-view/items/:id/versions/:n/file?path=` (`work.ts:45-95`).
5. **The client's version pills change only labels** (`ClientReviewQueue.tsx:44,78,164`); the files list names the
   chosen version but lists the current files (team too: `JobModelItems.tsx:531-536`).
6. **The team panel shows the previous item's picture and caption while the next one loads** (`versionsData` is not
   cleared or checked by `item_id`; `JobModelItems.tsx:63,77-97,335`), with Approve enabled.
7. **The Review queue shows a generic icon for every post**: it reads `item.thumb`, which `GET /review` does not send
   (`Review.tsx:290-309`, `approvals.ts:323`); posts can be bulk-approved unseen. Row meta prints three bullets; the
   words "Changes requested on v1" are hard-coded (`Review.tsx:324-326`, `JobModelItems.tsx:484-485`).
8. **List thumbnails load full originals** through `/file` (`JobModelItems.tsx:352-360`, `lib/clientItems.tsx:23`); on
   the client every such load is logged as a "download" (`app.ts:363-365`). `/thumb` exists for both and logs nothing.
9. **Client, non-post items show nothing**: files are names only (no way to open one), `preview.text` and `preview.url`
   are never drawn.
10. In the team panel the decision buttons sit under the files and the whole comment thread; the item under review gets
    the narrower column.

## Fix (web; one shared component for both sides)
A. `web/src/lib/item-preview.ts`: a typed `ItemPreview` and one normaliser `previewOf(raw)` that accepts both caption
   shapes (array and legacy object), defaults every field (`platforms`, `format`, `ratio`, `kind`, `media`, `text`,
   `url` may be null or missing) and returns `captions: { platform | null, text }[]` collapsed to one unlabelled block
   when every platform carries the same text. `captionBlocks` is rebuilt on it. Tests for both shapes, the collapse,
   nulls, a story (no caption).
B. `web/src/components/review/ReviewItemView.tsx` (+ CSS): draws ONE item version for review:
   - **media** at its real shape: no crop (`contain`), the stage sized from the post's ratio when the preview has one
     (else from the loaded media), all media pageable (reuse `MediaCarousel` where it fits), images, `<video controls>`
     for video, a file tile with an Open link for anything else; the bytes come from the **version file route** of the
     viewed version (team or client variant, a URL helper in `web/src/api`), with one `onError` fallback to the current
     file route; a broken media shows a named placeholder, never a broken image;
   - **context line** for a post: platform icons, format word, ratio;
   - **the copy in full**: a "Caption" block per platform (or one block when they are the same), rendered as Markdown
     (the field is `md`), never clamped; "No caption on this version." only when there is none; for non-post items the
     `text` and the `url` (as a link);
   - **files of the viewed version** (from the versions response), each openable through the version file route.
   Props: the item, the viewed version (n, preview, files), a `side: "team" | "client"` switch for URLs and words.
   It does not use `PostFrame` (clamped caption, team-only `/post-formats`, team-only toggles); the frame stays in
   the post editor.
C. Team Job panel (`JobModelItems.tsx`): uses `ReviewItemView` for the selected item and version; never shows another
   item's version (`item_id` check, cleared on change); the decision block moves directly under the view; the detail
   column gets the larger share through a modifier class on the grid (the shared `.workspace-grid` and `.preview-box`
   rules are not changed for other screens; `.preview-box` goes when it has no user left); list rows use the thumb
   endpoint with a video / file fallback; the "Changes requested" pill reads the version the client answered.
D. Client review (`ClientReviewQueue.tsx`): uses `ReviewItemView` with the picked version's preview and files; the
   version pills change what is shown; caption words in `copy.ts` and `copy/ar/copy.ts` (الكابشن · مفيش كابشن على
   النسخة دي · افتح الملف). List thumbs (`lib/clientItems.tsx`) use `/thumb`, with a fallback tile for video / file.
E. Team Review queue (`Review.tsx`): each row shows the item's thumbnail from `preview.media[0]` (thumb endpoint,
   fallback tile), the platform icons and a two-line caption excerpt; one bullet between meta parts; the "changes
   requested" line names the real version.
F. Mock: post items carry the live array caption shape; at least one post with several media, a video post, and two
   versions, so the vite mock shows the fixes.
G. Server, tests only (`tests/v1-job-model.test.ts` or next to it): for a created post, `GET /items`, `GET /review`,
   `GET /client-view/items` and both versions routes return `preview.captions` as `[{platform, md}]`; the version file
   routes serve the bytes of the asked version after the file was replaced (team and client).

Not in this ticket (recorded): Approve / Edit on the Review queue card and the client review layout of mockups 06 / 08
(S4-04, S5-04, not approved); a publish date on items (the server does not send one); video posters (no server
thumbnail for video); "approve all" on the client Home (decision 6); deleting the dead `PostsList` / `client-review.ts`.

## Acceptance
1. Team, a post saved by the current code: the Job panel shows its caption in full for every platform (one block when
   equal), as Markdown; the legacy object shape still shows; a story says there is no caption.
2. Client: the review screen shows the same caption blocks, in Arabic and English.
3. Media is never cropped; a 4:5 and a 9:16 post show whole; every media of a carousel can be reached; a video plays;
   a PDF or other file opens through a link; no broken image in any case (placeholder instead).
4. The picture and the files belong to the version shown: after a file is replaced, v1 shows the old bytes and v2 the
   new ones, for the team and for the client (the client under re-review sees the new version's picture, not the
   live one); a version with no stored snapshot falls back without a broken image.
5. Client version pills change the preview, the caption and the files list.
6. Switching items in the team panel never shows another item's picture or caption.
7. The Review queue row of a post shows its thumbnail, platforms and a caption excerpt; one bullet between meta parts;
   no hard-coded "v1".
8. List thumbnails (team job list, client lists) load through the thumb endpoint; a client list no longer writes
   "download" activity rows by listing items.
9. Non-post items: the client can open each file of the version and sees the item's text and link.
10. The team decision buttons sit directly under the item view; the detail column is the wider one at desktop; the
    client review grid and every other user of the shared classes are unchanged unless stated.
11. One component (`ReviewItemView`) draws the item for both sides; `ds:check` rules hold; 44px controls on the phone;
    no horizontal scroll at 390.
12. Server tests pin the caption shape on the five reads and the version file routes (team and client).
13. Checks green: root typecheck, lint, `npx vitest run --no-file-parallelism`; web typecheck, `ds:check`, build,
    `test:api`. No migration, no route change.
