## 2. Design
### 2.1 The read: `GET /client-view/growth?month=YYYY-MM` (access `client`)
Returns 404 `{code: "not_found"}` with the app's polite not-found words unless `clientSettingsOf(brand).show_growth_report` is true AND at least one result exists for a client-visible campaign of the brand (decision 5; Q2). Else:
```
{ months: ["2026-10", ...],            // only months holding a result of a client-visible campaign, newest first
  month: "2026-10",                    // the asked month, default the newest
  delivered: { ... },                  // the numbers of clientReports for that month (S5-03 PR a maps the four drawn ones)
  stages: [ { stage, metric, unit, value, goal: {target, due_at} | null, previous: {month, value} | null } ],  // the five stages, in order
  here: { stage, campaign, milestones: {done, total} } | null,
  next: [ { title, due } ] }
```
Rules (the drawing, SPEC section 3): a stage row has a number only when it has a result AND (a goal for it OR a result in the previous month); every other stage is `value: null` and the page writes "Not measured" (the revenue row of the drawing: nine orders typed, no goal and no previous month, so no number is shown; the drawing's small "9 orders reported ..." line is a designer's note and is not built, Q3). Only client-visible campaigns count; a hidden campaign adds no row, no month, no number. `here` and `next` come from the existing plan reads and need the Plan and Milestones switches (`show_plan`, `show_milestones`); with a switch off the block is absent. No `reported_by`, no names, no target of a hidden campaign, no ids of users: the keys are exactly the ones above (a test lists them). Every number is labelled "reported by team" by the page, not by a field.
"A word from your account manager" (free Arabic text in the drawing) has no stored source and no name is allowed: **not built** (Q5). "Next month" lines come from `next` (the next open client-visible milestones), not typed text.
### 2.2 The page
`/client/report` (`web/src/pages/client/ClientReport.tsx`): title "October result · <client>" and "Numbers reported by the team"; month segment (44px, under the title; only `months`); blocks Delivered, What it produced (five rows as drawn), We are here, Next month. A month with no result yet is not in the segment. A 404 from the read shows the existing "not available" page, never an error banner. The menu link "This month's result" appears only when `show_growth_report` is on and `months` is not empty: the client profile read gains `sections.growth` (true only then), so the link needs no extra call; with the switch off the menu and every old page are byte-identical.
### 2.3 Route and words
`/client/report` goes into `shared/routes.json` `pages` (one line). A server test (the pages test of S2-07) fails if the file and `App.tsx` / `spa.ts` disagree; and a test that the path answers the SPA shell (200) signed out like its neighbours. Words in the client dictionaries, English and Arabic, same shape; the Arabic is the drawing's (الاستقطاب / التفعيل / الإيراد / الاحتفاظ / الإحالة, "مش متقاس", "مسجّلة من الفريق"; decision 8 still asks Ahmed to confirm the stage words, Q6).

## 4. Acceptance
1. Switch off (the default): the read answers 404 for every client, with and without results; the profile has `sections.growth = false`; no new link (`growth-report: off = nothing`).
2. Switch on, no result, or only results of a hidden campaign: 404, `sections.growth = false`.
3. Months: only months with a result of a client-visible campaign; newest first; `?month` outside the list is 404; a bad format 422.
4. Stage rows: value only with a goal or a previous month; a stage with a result and neither is `null`; with a goal and no result is `null`; the percent of goal and the "vs previous" are computed in the builder, tests table-driven.
5. A client sees nothing the team did not choose: a hidden campaign, a hidden milestone, `show_plan` off, `show_milestones` off each remove their part (`here`, `next`); `reported_by`, names, user ids, `updated_by`, `source` never appear.
6. Another client's brand never leaks: results of brand B are absent from brand A's answer; a link scoped to jobs reads the brand's report as the other client reads do (`client-view/reports` precedent; the builder states it).
7. `tests/client-payload-walk.test.ts` walks `client-view/growth` with the switch on and results seeded (200) and finds no `FORBIDDEN_KEY` and no team id; the walker's forbidden list gains `reported_by`, `reported_at`, `updated_by`, `source`, `target_user` for all walked answers.
8. `shared/routes.json` contains `/client/report`; the pages test and the SPA-shell test are green.
9. Page as drawn at 1440 EN light and 390 AR dark, with the 09 insets: (a) link only with a result, (b) a running month with nothing reported shows the Delivered block only. No account-manager name, no "Send link", no owner controls.
10. Gate `web/qa/S5-03/gate.mjs` (390 and 1440, light and dark, EN and AR): every drawn state; "reported by team" next to every typed number; 44px targets under 768; text at least 4.5:1; no stroke; no sideways scroll; switch off (default mock client) shows no link and `/client/report` shows the polite page; month change fetches once.

## 6. Owner questions (defaults let the build proceed)
1. Owner view: default none; the team checks a client's page through "View as client". A Reports > Growth tab is a later ticket if Ahmed wants it.
2. Link rule (decision 5): switch ON and at least one result (default).
3. A stage with a typed number but no goal and no previous month: default "Not measured" with no number (plan rule). Alternative: show the bare number.
4. The four "Delivered" numbers: default the system's own review counts of `clientReports` for the month (no new count).
