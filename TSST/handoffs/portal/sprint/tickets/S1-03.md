# S1-03: CI workflow

Part S1 (safety). Gate: none. Depends on: nothing. Approved by Ahmed 2026-11-06.
State lives on `../BOARD.md`; this file holds the scope, the acceptance list and the evidence.

## Problem
The repository had no automatic checks. They were run by hand on one machine, `scripts/deploy.sh` runs none of them,
and the 404 bug of S0-01 stayed live because nothing ran the tests.

## Scope
Repo `~/Work/tsst-portal`, branch `sprint/s1-03-ci` from `origin/next` (`8915d14`), worktree `~/Work/tsst-portal-s1-03`.
PR [#29](https://github.com/AhmedFouad01/tsst-portal/pull/29) into `next`.

- `.github/workflows/ci.yml`: two jobs on every pull request into `main` or `next` and on every push to them.
  - Server: `npm ci`, typecheck, lint, `npx vitest run --no-file-parallelism`.
  - Web: `npm ci`, typecheck, `test:api`, `ds:check`, the live build, then the checks `deploy.sh` makes on that build.
  - Node comes from `engines.node` in `package.json` (24.18.0). Read-only token, no secrets.
- `scripts/check-live-build.sh` (new): the "fit for production" checks of `deploy.sh` (no source maps, no mock files or
  markers, no inline script), run by CI after the build. `deploy.sh` itself is not touched.
- `web/src/styles/job-model.css`: one line. A raw `1px` (twice) becomes `var(--size-1)`, which is `1px`. The
  design-system check had failed on `main` since `48bb42f` (2026-11-04) because of it. Nothing changes on screen.

Not gated yet: web eslint (265 old errors) and the Playwright suite (needs a running server).
Not in this ticket: branch protection. It waits for Ahmed's OK (decision 12). Until then a red check warns but does not block.

## Acceptance
1. The workflow runs on every pull request into `main` or `next`, and on every push to them.
2. Server job: `npm ci`, typecheck, lint, the whole suite, on Node 24.18.0.
3. Web job: `npm ci`, typecheck, `test:api`, `ds:check`, live build.
4. Both jobs green on the pull request.
5. A pull request with a type error turns red.
6. No write permission, no secrets.
7. No product behaviour change.
8. Branch protection is not part of the ticket.

Plan wording kept for the record: "A PR with a type error is blocked" needs branch protection (decision 12);
"CI green on main" comes when `next` is merged into `main` at a deploy gate.
