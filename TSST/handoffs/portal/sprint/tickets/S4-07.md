## 3. The read model
**`GET /home/week?view=mine|everyone&offset=0&person=<user id>`** (access `team`). `view` as Today (default `mine`; `everyone` 403 for a member; bad value 422). `offset` = whole weeks from the current week, integer -12..12, default 0 (else 422; the server derives the Saturday, no free `start` date). `person` = owner on Everyone only: the rows that would be on that person's Mine, drawn with `.who`; a member sending it 403; unknown or inactive user 422.
```
{ today, viewer:{id,name,role}, view, person:{id,name}|null,
  week:{ start, end, offset, current },                          // Saturday .. Friday, YYYY-MM-DD (Cairo)
  settings:{ working_days:[6,0,1,2,3,4], labels:{ "6":{en,ar} } },   // 0 = Sunday .. 6 = Saturday; labels only for weekdays that have one
  days:[ { date, working, today, past, label:{en,ar}|null,
           counts:{ tasks, make, review, schedule, waiting, out },
           tasks:[Row], make:[Row], review:[Row], schedule:[Row], waiting:[Row], out:[Row] } ] }   // always 7 days
Row = HomeTodayRow + { group, quiet, sent, goes_out, ready_count, first_goes_out }   // new fields null / false where not meant; `done` for a task
```
- Core: `homeFacts` gains `{ includeDone: true }` (passed to `turnsOf`), a `subject` (whose Mine; defaults to the viewer; `withOf` still says "you" for the real viewer), and a task window of the week with `done` unset (done tasks in the window + open ones overdue before today). `weekRows(facts, env, world, {offset, settings})` is pure and reuses `jobRow`, `taskRow`, `withOf`, `needsAction`, `waitingOnOthers`, `isOpenTurn`; no second loader. The week's day set and the Cairo `submitted_at` day use `core/day.ts`.
- **Query budget** (beyond `loadWorld`, which the route does as Today does): `homeFacts` 7 + the week setting 1 = **8**, the same for 1 and 8 items, 2 and 5 clients, 0 and 20 tasks (`includeDone` adds rows in memory, never a query). Test: the query recorder of `v1-home-today-view.test.ts`, three sizes.
- A client **without a review order** (every real client now): no `planned`, no `submitted_at`, so no sent rows and no Planned rows; `review` is the earliest active owner's (Mine of that owner only; other owners on Everyone); `changes` with no maker is the owners group; `ready` and Going out work the same. A client **with** an order adds Planned and sent rows, `approval` held by a team member (chip "Waiting on approval"), `waiting` for the maker. Tests run both.
- **The working days setting.** Stored in `portal.settings` under key `week`, value `{ working_days: int[], labels: { "0".."6": { en?: string, ar?: string } } }`. Default when the row is absent: `[6,0,1,2,3,4]` (Saturday to Thursday), no labels. Validation (`exact`, as `workspace.ts:183`): `working_days` 1 to 7 distinct integers 0..6 (zero days is 422), saved sorted in week order; label keys `"0".."6"` only, each `en` / `ar` trimmed, at most 40 characters, no control characters, empty = unset; unknown keys 422. Routes: `GET /settings/week` and `PUT /settings/week` (owner; the PUT returns the stored value, audited like the workspace PUT with `updated_by`). Every member reads it inside the Week answer, so no member route. The row never appears in `GET /workspace` (branding allowlist `branding.ts:131`) nor in any client payload (walk test).
- **Migration `037_week_setting.sql`** (pure add): `ALTER TABLE portal.settings DROP CONSTRAINT settings_key_check; ADD CONSTRAINT settings_key_check CHECK (key IN ('visibility','workspace','drive','company','week'))` (the constraint name and list as `018:9-10`; the builder confirms the live list from the last migration touching it). No data. Rollback (a down note in the file, local database only): `DELETE FROM portal.settings WHERE key='week'` then restore the four-key check. Written and run on a local database only (BOARD rule 8), with the restore drill before any deploy that carries it.
- Weekday labels: the drawing needs them (in-house frames 3 and 4; P9 "shown only where set"), so the setting holds them now; nothing draws them for an agency that sets none. The page shows the label of the page language, else the other one.
