## Design

### 1. The tab
`?tab=settings&s=people|package|visibility|language|danger` (`s` defaults to `people`; an unknown `s` → `people`; a team
member's `s` other than `people` → `people`). Layout `.settings`: desktop = a 240px section list (`settings__list`:
five entries, Danger in the danger colour, under them the muted line "Team members see People & access only.") + the
content column; phone = a sticky, horizontally scrollable pill row of the five pills (44px, selected = surface + royal
text) above the stacked sections. On desktop every section renders in order and the list entry scrolls to it and marks
`s`; on the phone the same. Section = a `Card` with `card__head` (title, the "Saved" word when the last save succeeded,
the one primary action at the end). Every control saves on change (one field per `PUT`), shows "Saved" / "اتحفظ" in the
section title for a few seconds, and an error `Notice` under the control on failure. No draft + Save bar anywhere.
Team members (role team) see only People & access; the list and the pills show the one entry.

### 2. People & access (`s=people`)
- Head: "People & access", action `Invite person` (primary, sm) → the existing invite form as a `Modal` (name, email,
  role); the setup link result stays as today.
- Rows (`row--person`): avatar with initials (`.pav`, two tints), name, sub "email · last sign-in <relative>" (active)
  or "setup link sent, not opened yet" (invited); role chip `Approver` (`chip--approved`) / `Viewer` (`chip--neutral`);
  ⋯ menu per person: `Resend setup link` (invited only), `Make approver` / `Make viewer`, separator, `Remove…` (danger,
  `ConfirmDelete` as drawn: "Remove <name>?" / "They lose access to <brand>'s portal right away. Their comments stay on
  the items. You can invite them again later."). Removed people are not listed.
- Empty: "No one from <brand> has access yet" / "Invite the person who approves work; they sign in by email code."
- "Client address": the address in `.addr` (`client_url`), hint "Copy it, or view the portal as the client, from the ⋯
  menu on the title row." (no buttons here: one action one control).
- "Account manager" (owner only): `LabeledSelect` of `GET settings/team` users (name; "—" = none), saving
  `account_manager_user_id` on change. Team members see the name read-only (or "—").
- "Old links (n)" fold (`.fold`, closed by default; hidden when n = 0): rows "…/c/<last 8 chars>" · label · opened n
  times · expires <date> or chip `Expired <date>` (`chip--ended`), one `Revoke` (danger, sm, `ConfirmModal`) per row.
  No create, renew or reset-PIN controls on the page any more (the routes stay).
- Activity: the existing `ClientActivity` list moves under People as a second fold "Activity" (closed by default) so
  nothing is lost; S4-06 may move it.

### 3. Package & billing (`s=package`)
- Head: "Package & billing", action `Add package` (primary, sm) → `AddPackageModal`.
- Held packages as rows: title "<plan> · <price> / <period>", sub "Active since <start> · renews <period_end> · bonus
  +n <line> (<month>)" (the parts that exist), status chip (`chip--active` / paused / ended / delivered as
  `status-words.css` draws them), ⋯ menu with the existing package actions (pause / resume / end / deliver / delete with
  their confirms). The money actions leave this page: no Mark paid, no Create invoice / receipt here.
- Under the primary package: the four `pk-line` tiles (Campaigns, Ads, Hours, Edit credits: "<n> / month"; a line the
  plan does not include reads "—"), then Platforms as tags and Next payment "<date> · <amount>" (read-only text; the
  date is set in Documents).
- One link "Invoices and payments in Documents" → `/documents?brand=<brand>` (check the Documents page's query key;
  use what it reads). `ReadyToBill` leaves the client page; it is rendered on the Documents page for the owner (above
  the list, filtered by `?brand=` when present) so the function is not lost. If the Documents page cannot take it in
  this ticket, keep it as a closed fold at the end of this section and say so in the PR.
- Empty: the existing packages empty state with the Add package action.

### 4. What the client sees (`s=visibility`)
- Head: "What the client sees" + Saved word. Rows (`switch-row`): Package ("Usage lines on the client Home"), Billing

  `show_milestones`, `show_plan`, `show_growth_report`, each its own `PUT`.
- "Projects": one switch row per project (General excluded): name, sub "Visible" / "Hidden", with "Closed · " first

### 5. Language & branding (`s=language`, owner only; team members do not see it)

  `/clients/view?brand=<b>&tab=settings&s=language`; its per-client form is removed (S4-06 owns the global pages).

## Acceptance
1. `?tab=settings` shows the five sections in order with the desktop list / phone pills as in § 1; `s=` selects and
   scrolls; a team member sees People & access only (list, pills and content).
2. People & access: rows, chips, ⋯ (resend only when invited; role switch; Remove behind the drawn confirm), Invite
   person as the one primary action, the empty state, the client address with no buttons, the account manager select
   (owner) saving `account_manager_user_id` with an error shown on 422, the Old links fold with Revoke only, the
   Activity fold. No create / renew / reset-PIN control remains in the web (grep is empty).
3. Package & billing: rows with status chip and the package ⋯ actions, the four lines, platforms, next payment
   read-only, Add package, the Documents link; no Mark paid / Create invoice / receipt control on the client page;
   `ReadyToBill` reachable on Documents (or the fold fallback, stated in the PR).
4. What the client sees: five switches on the five settings fields (one `PUT` each) and the project rows; the Saved word
   after each save; an error Notice on failure.
5. Language & branding (owner): language, display name, industry, logo, header image, Instagram, Facebook; each saves
   on change with the Saved word; `settings/Clients.tsx` is a list linking into the tab, no per-client form left there.
6. Danger (owner): Delete client behind the drawn confirm; the title-row ⋯ has no Delete any more; no Archive control.
7. Every control saves on change; no Save bar; `ds:check` rules hold (no native controls, no numeric spacing).
8. Matches mockup 02 at EN 1440 light: 240px list + content, cards, rows, chips, pills on the phone (44px, sticky, one
   column). AR words of § 7 in the AR copy and tested (the live AR frame waits for a team language switch, as S3-02).
9. Nothing the team could do from the interim Settings tab is lost, except the link-creation controls the mockup
   removes (listed in the PR body, with where each action lives now).
10. No API or migration change (`src/`, `migrations/`, `shared/` untouched; if `shared/routes.json` or `tests/`
    must change for a link, say why).
11. Checks green: web typecheck, `ds:check`, build, `test:api`; root typecheck, lint, `npx vitest run
    --no-file-parallelism` when anything outside `web/` changes.
