# S2-06 — server split by domain

Plan: "`src/server/v1` regrouped into clients, work, approvals, publishing, plan, commerce, requests, reports; access
checks as middleware; `endpoints.ts` grouped the same way." Acceptance: no file named by access level or round; all
tests pass unchanged. Size L, gate none, depends on S2-03 (merged). No migration, no behaviour change.

## Design
### Nine domain files replace the twenty (`src/server/v1/`)
Every route keeps its method, path regex, access level, handler and helpers; only the file changes. Each domain file
defines `route(method, path, access, handler)` with the access level written at every route (no helper bakes it in).
| File | Routes (from) |
|---|---|
| `clients.ts` | `clients`, `client` (team-read); `client/settings` GET/PUT and the two `settings/visibility` 410s (owner); the two `settings/clients/:b/visibility` 410s (client-profile); `settings/clients` GET, `settings/clients/:b` PATCH 410 / PUT, `logos`, `logo-preview`, `client-view/profile` (branding); all 16 of client-accounts; the 2 of client-pin; the 6 of access (links); `DELETE settings/clients/:b` and `DELETE settings/clients/:b/people/:id` (soft-delete). |
| `work.ts` | `me`, `home`, `jobs`, `job`, `folders` (team-read); `POST jobs`, `PATCH jobs/:id`, `drive/import`, `job/meta`, `job/archive`, `job/restore` (team-write); `items` GET/POST, `items/:id` PATCH/DELETE, `items/:id/versions` GET/DELETE, the two version-file routes, `sync`, `job/model`, `job/files` GET/PATCH, `client-view/items`, `client-view/items/:id/versions` (items); the 4 of time; `PUT/DELETE media` (plans-media); `DELETE job` (soft-delete); `client-view/home`, `client-view/job` (client). |
| `approvals.ts` | `items/:id/decisions`, `items/:id/withdraw`, `job/release-early` GET/POST, the 8 comment routes, `client-view/items/:id/decisions` (items); `review`, `feedback` (team-read); the 410s `PATCH job/items`, `POST decisions`, `decisions/batch` (team-write) and `client-view/decisions` (client). |
| `publishing.ts` | the 5 of posts; the 4 of post-ads; `client-view/posts` (client). |
| `plan.ts` | `plan`, `client-view/plan`, `client-view/project` (client-profile); the 5 of projects; `milestones` GET (team-read), POST/PATCH/DELETE (team-write); `plans/preview`, `plans/import` (plans-media). |
| `commerce.ts` | `settings/plans` GET/POST/PATCH (owner) + DELETE (soft-delete); `settings/bonuses` ×4; `settings/time-estimates` ×2; `client/package`, `client/packages` POST/PATCH/DELETE, `client/payments/paid` (owner); `client/packages` GET (team-read); the 10 of documents; `clients/:b/ready-to-bill` (team-write). |
| `requests.ts` | `requests` GET, `requests/:id/price`, `PATCH requests/:id`, `DELETE requests/:id` (team-write); the 5 `client-view/requests*` (client). |
| `reports.ts` | unchanged (2). |
| `workspace.ts` | `workspace` (public), `settings/workspace` ×2, `settings/company` ×2 (branding); the 4 of team-admin; `DELETE settings/users/:id` (soft-delete); the 2 of invite. |
- A helper used by one domain lives in that domain's file; one used by several moves to `src/server/v1/shared.ts`
  (`knownBrand`, `packageEntry`-style helpers, the brand/job lookups) or to `core.ts` when it is a request helper.
  Service modules under `src/service/` do not move.
- `index.ts` assembles `[...clients, ...work, ...approvals, ...publishing, ...plan, ...commerce, ...requests, ...reports,
  ...workspace]`. Every path is anchored (`^/api/v1/…$`), so order only matters where two regexes overlap; the builder
  checks the overlaps (`([^/]+)` next to a literal sibling) and keeps the old relative order where they do.
### Access checks as middleware
The inline block `index.ts:97-116` becomes `guard(route, session, request)` in `src/server/v1/guard.ts`, called once by
`handle` before the handler: same four answers (client 401, login 401, owner 403, same-origin 403), same messages.
### Web
`web/src/api/endpoints.ts` keeps every function name and body; the functions are regrouped under nine section comments
in the same order and with the same names as the server files. `delete-calls.test.mjs` is order-free. The mock does
not change.
### Acceptance, as the reviewer reads it
1. `ls src/server/v1` = `clients.ts work.ts approvals.ts publishing.ts plan.ts commerce.ts requests.ts reports.ts
   workspace.ts shared.ts guard.ts core.ts index.ts`; no file under `src/server/v1` named by access level or round.
2. The route table is the same set: a script lists `(method, path.source, access)` from `ROUTES` before and after and
   diffs to empty (the builder keeps the before-list in the PR body).
3. `tests/` unchanged except the two direct imports, which still resolve; the full suite passes with the same count
   (714) and no test edited.
4. `docs/DASH-API.md` gains one short section naming the nine files; nothing else in the docs changes.
