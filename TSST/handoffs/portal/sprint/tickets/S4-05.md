## 2. The change
No migration, no new route, no new page path (`/requests` is already in `shared/routes.json`). No server change.
- **Nav (owner only):** a "Requests" entry in the main list after Review, with a count badge of requests with status `requested`; no badge at zero; capped "99+". Count from `useJobRequests(undefined, 'requested')` (`lib/jobRequests.ts`), which reloads when any request is saved. A member does not get the entry and **does not call the list** (no request fired for them). On the phone it sits in the More sheet with its badge; the More button gets a dot when the count is above zero (Q2).
- **Three tabs instead of seven** (Q1 default): **New** (`status = requested`, whatever the price state), **Accepted** (`status = accepted`), **Closed** (declined, done, cancelled). The price state shows on the card as it does now (status chip, band) instead of being a tab. The tab shown by address: `/requests?tab=new|accepted|closed` (default New); the existing `?brand=` stays. Counts in the tab labels.
- **Accept and Decline visible** on a New card as two buttons beside the price button; the `...` menu keeps Update status, Edit request, Delete. They open the same `JobRequestEditor` modes as the menu does today.
- **Price inline, Create jobs, Bill:** already there; kept as they are. "Bill" stays the "Ready to bill" line that links to Documents; no new billing step.
- **Client:** the badge of a priced request reads **"Price to approve"** (Arabic default «سعر محتاج موافقتك»), through the client dictionary `copy/ar/client-ui.ts`. Nothing else on the client page changes; a client with no priced request sees no difference.
- Empty states per tab in words (copy in both files). Page title and tab words go to `web/src/copy.ts` and `web/src/copy/ar/copy.ts` (the page's English is typed in the code today, `Requests.tsx:13`, `:27`, `:33`).
