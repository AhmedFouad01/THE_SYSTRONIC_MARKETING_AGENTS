## 2. The change
**Data.** None. A task = a milestone whose `owner_id` is not null. No new column, table or migration (037 stays free). Rollback = revert the code. No backfill: old milestones with an owner become tasks by definition. A task whose owner left the team keeps `owner_id`; it shows with "(inactive)" (`milestoneModal.inactiveOwner`) and only in Everyone.

**API (additive; every existing call answers as before).**
- `GET /milestones` gains `owner` (a user id, or `me` = the caller, or `none` = no owner) and `overdue=include`. Answer: the same `Milestone[]`, ordered `due, id`; no new field. With `overdue=include` the answer is the union of (rows in `from`..`to`) and (every open row with `due` < today, Cairo), whatever `from` / `to` say; a done row before `from` stays out. Without `overdue` nothing changes. Filter pushed into `listMilestones` (`jobs.ts:523`) as SQL conditions `m.owner_id = $n` / `IS NULL` and the `OR` above; today's Cairo day from `todayOf(c.deps.now())`. Errors: 422 `invalid` for an `owner` that is not a uuid, `me` or `none`, and for `overdue` other than `include`. An unknown uuid answers `[]`. Deleted clients, jobs and milestones stay out as today; archived jobs are **not** filtered (as `GET /milestones` today); Home decides that.
- `POST` / `PATCH`: the owner must be `activeUserSql` (active and not soft-deleted); `PATCH` does not re-check an `owner_id` equal to the one already on the row. A malformed id answers 422, never 500 (test it). `owner_id: null` clears it. Unknown fields still refused.
- Rights (default, see Q2): unchanged. Any team member creates, assigns to any active person, ticks (`done`), edits, reassigns and deletes; so the owner of a task may tick it. Mine / Everyone is a Home view, not a permission: every team member can already read every milestone.
- **Client**: an owned milestone may still be `client_visible` (a campaign milestone with an owner is normal). A client sees the same milestone as today with `owner: null, owner_id: null`; a task made by the New task sheet is saved `client_visible: false`, so it never reaches a client by accident. `clientMilestone` and the plan reads stay as they are; the proof is the walk test (acceptance 6).

**Web (minimal; no Home).**
1. `web/src/lib/tasks.ts`: `isTask(m)` = `owner_id !== null`; `newTaskBody({ title, ownerId, due, brand, projectId })` -> scope `project` with `project_id` when a campaign is chosen, else `client`; `client_visible: false`; title trimmed; `ownerChoices(people, currentOwnerId, words)` = active people, plus the current owner as "(inactive)" when not active.
2. `NewTaskSheet.tsx` (props `brand`, `onClose`, `onSaved`; the ds `Modal`, as `MilestoneModal`): Title, Owner (default: the signed-in user), Due date (default today, Cairo), Campaign (optional; "no campaign" + this client's campaigns from `api.getProjects`), Cancel / Save, exactly as in the drawing; no Client field and no "client visible" switch. Empty title: the dialog's existing `needFields` error. S4-01 reuses this component and adds the client choice when opened from Home.
3. Mounted on the Plan tab milestones card next to "Add milestone": a button **New task** (Q1). The card shows a row's owner name (person icon + name, as `MilestoneEditor.tsx:80`) when `owner_id` is set; the existing numbered tick stays the row's one control; the Overdue chip stays. The campaign / client rows keep the name "milestone"; the word Task appears only on the New task button and sheet.
4. `MilestoneModal`'s Owner list reads `api.getTeamPeople()` (every team member, not only the workspace owner); the former owner still shows as inactive.
5. `getMilestones` accepts `owner` and `overdue`; mocks (`mock/client-plan.ts:73`, `:98`; `mock/planning.ts:137`) honour them and set `owner` from the people list.
6. Words in `web/src/copy.ts` and `web/src/copy/ar/copy.ts`: Task / تاسك, Tasks / تاسكات, New task / تاسك جديد (SPEC section 2); Owner, Due date, Save, Cancel reuse the existing `milestoneModal` words; "Campaign (optional)" is the one new phrase besides these three, and needs its Arabic from Ahmed (Q3).
