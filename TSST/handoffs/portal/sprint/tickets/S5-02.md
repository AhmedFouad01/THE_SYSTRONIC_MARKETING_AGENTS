## 2. Design
### 2.1 Routes (new, `src/server/v1/plan.ts` next to the projects; access `team`, Q1)
| Route | Body / query | Answer |
|---|---|---|
| `GET /projects/:id/growth` | none | `{ project: {id, name, type, stages}, catalogue: [{id, stage, unit}], goal: {stage, metric, unit, target, due_at, updated_by, updated_at} \| null, results: [{stage, month, metric, value, reported_by, reported_at}], months: ["2026-11", ...] }`. `months` = from the campaign's start month to the current Cairo month, newest first (at most 24). General or ongoing project: 404 |
| `PUT /projects/:id/goal` | `{stage, metric, target, due_at}` (exact keys) | the saved goal. One call saves the whole goal: a goal needs all four, so the form saves once the four are valid and then on each change |
| `DELETE /projects/:id/goal` | none | 204 |
| `PUT /projects/:id/results` | `{stage, month: "YYYY-MM", metric, value}` | the saved row. One field = one call = one row |
| `DELETE /projects/:id/results` | query `stage`, `month`, `metric` | 204 (an emptied field) |
Rules and statuses are S5-01's functions (stage the campaign has; pair in the catalogue; month not in the future; integers). Unknown keys 422 (`exact`, as `plan.ts:155`). `actor` = `c.user.name`. Last write wins on one field; two members editing different fields never collide. The catalogue travels in the answer so the web has one source; the web holds only the words by id.
Docs: `docs/DASH-API.md` and the route table, regenerated with `scripts/route-table.ts --write` (the test of S2-07 fails if stale).
### 2.2 The Direction tile (read only)
`direction` gains `goal: { stage, metric, unit, target, due_at, latest: { month, value } \| null } \| null` in `clientOverviewOf`, for the campaign `campaignOf` already picks (so tile and goal are the same campaign). Two queries keyed on `campaign.id`, none when there is no campaign. The tile adds one row after Milestones, only when `goal` is not null: "Goal: Showroom visits · 96 of 120 · reported by team" with a result; with no result yet: "Showroom visits · goal 120 by 30 Nov · no result yet". No goal: no row (nothing drawn). Web type and mock updated.
### 2.3 The campaign page (web)
A new card "Goal and results" between the head and Milestones, for a campaign only (not General), one `GrowthCard` component.
- **Goal:** Stage (the campaign's own stages), Metric (the catalogue rows of that stage; one row means a fixed word), Target (whole number), By (date). Empty state: "No goal yet" and the first two fields. Saves when the four are valid, then per change on blur or choice; clear = a text button with a confirm.
- **Results by month:** one row per month in `months`; one number field per catalogue metric of the campaign's stages (stages without a metric are not drawn). Blur saves (`PUT`), an emptied field deletes (`DELETE`), a typed 0 is a value. Each field shows its own state (saving, saved, error with the server's words and the old value kept). Under the card: "Reported by team". Team-only line per entered field: "Ahmed Samir, 5 Nov" (title or muted text; it never reaches a client).
- Phone 390: months stack as cards, one labeled field per metric, 44px targets. Tokens only; words in `copy.ts` and `copy/ar/copy.ts` (same shape); numbers use `num` / `<bdi>`; `ds:check` green.
