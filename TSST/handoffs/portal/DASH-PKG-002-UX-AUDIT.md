## Top 5
1. A1 Package management leaves Settings and moves into the client page (list, add, pause, end, deliver, delete, payments).
2. A3 Payments are keyed by `due` only; with several packages one click marks the wrong row. Key by `package_id` + `due`.
3. A4 Invoice rows: qty x unit price = line total, "Add package" picker, drop the "package value" override for new documents.
4. A8 One honest line for each plan: price, instalment, every N days, hours and credits explained in field hints.
5. A9 Rename the period option "Lifetime" to "All time" (clashes with Lifetime packages) and show all packages on Home / client views.

## B. New pieces (HeroUI v3 / our ds wrappers)
**B1 Plan form (Settings > Packages).** First field `SegmentedControl` (ds, HeroUI ToggleButtonGroup): Subscription | Lifetime; read-only chip when editing (API: kind cannot change). Then `TextInput` name, `SegmentedControl` currency, `NumInput` price ("Price per month" / "Price (one time)").
- Subscription shows: bill amount, bill every, campaigns, ads, hours, edit credits, request credits.
- Lifetime hides all of those (sent as 0), keeps Services (`TagGroup`) and Platforms (`CheckboxGroup`). Hint under price: "Paid once, no renewal."
- Actions: `Button` Primary Create / Save, `Button` Secondary Cancel; same width.

**B2 Client packages on ClientDetail** (`ClientPackages`, a `Card` with `Heading` count + `Button sm` "Add package").
- One `Card` row per package: name, kind chip (`Chip` "Monthly" / "Lifetime"), status chip (`PackageStatusChip`), start date, "next payment" line. Subscriptions first, then lifetime (API order).
- Row actions as `Button sm`: Pause / Resume (subscription), End (confirm), Mark delivered / Reopen (lifetime), Delete (danger, hidden when a payment is paid).
- Expand (`Disclosure`) = payments table (`Table` per A18): Due, Amount, Status, action Mark paid / Undo. Overdue uses `OverdueChip`.
- Add = `Modal` (sm): `FilterSelect` plan (archived hidden, plans already held greyed with reason), `DateInput` start ("Purchase date" for lifetime), Primary Add. 409 text shown in `Notice`.
- Empty: `EmptyState` "No packages" + Add package. Loading `LoadingState rows=2`. Mobile 390: row stacks, actions wrap into a `Dropdown` "More" below 640.

**B3 Client view (ClientHome, ClientHeader modal).** Header keeps the primary subscription name + "+ N more". "Package details" modal: `Card` per package. Subscription: name, status chip, usage `ProgressBar` rows, bonuses, next payment (only with `show_billing`). Lifetime: name, `Chip` "Owned", status Active / Delivered, services as chips, no bars, no price unless `show_billing`. Ended packages are hidden by the API. Period control last option "All time".

**B4 Invoice / quotation lines (`DocumentEdit`).** Panel "Items" with `Button sm` Secondary "Add package" (opens `Modal` with `ListBox` of plans: name, "Monthly / One time", price; search `TextInput`) and "Add custom line". New document "Start from": Blank / Client's packages (`FilterSelect`).
- Row at 1440: grid `Service+description (wide) | Qty (NumInput 1-36, only for monthly, label "Months") | Unit price | Line total (read-only text, `formatMoney`) | move up / down / remove IconButtons`. Qty fixed 1 for lifetime and custom lines (field hidden, not disabled).
- At 390: stacked, line total right-aligned under unit price, icon buttons in one row.
- Totals Panel: Subtotal, Discount (%), Total due; override Switch only for old documents, labelled "Fixed package value (old document)".
- Draft saved notice stays; lines sum shown live (not "Save to refresh the totals").
