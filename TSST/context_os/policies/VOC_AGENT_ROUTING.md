# TSST VOC → Agent Routing v0.4

Status: PROPOSED / UNVALIDATED

| Evidence pattern | Primary route | Secondary review |
|---|---|---|
| Repeated crash/error/integration failure | DEV_AG | LENS if business impact needs sizing |
| Navigation/RTL/table comprehension friction | CREATIVE_AG | DEV_AG implementation feasibility |
| "I expected X but product does Y" | LENS_AG | CREATIVE/DEV depending root cause |
| High-quality leads but low close due feature gap | Lead + LENS | DEV_AG feasibility |
| Poor lead fit / wrong promise | LENS_AG | SPARK_AG |
| Attribution/report inconsistency | SPARK_AG | DEV_AG |
| Campaign claim resonates but product doesn't support it | Lead | LENS + DEV + CREATIVE |
| Product works but users cannot discover feature | CREATIVE_AG | LENS messaging/onboarding |
| Frequent custom request from one account | LENS_AG evidence review | Lead; do not auto-roadmap |
| Repeated measurable outcome improvement | Lead + LENS | candidate product strength |

## Route by cause, not wording

A customer saying "I need feature X" is not automatically a DEV task.
First determine the underlying job/outcome and whether an existing capability, UX, configuration or expectation problem explains the request.
