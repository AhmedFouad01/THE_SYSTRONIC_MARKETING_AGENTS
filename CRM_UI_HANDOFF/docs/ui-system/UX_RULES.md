# UX Rules


1. Clean, formal, minimal and premium. Avoid decorative noise.
2. Hierarchy must come from spacing, typography, surface, content priority and controlled emphasis.
3. Do not use decorative colored top/side strokes as the default card/status pattern.
4. Selected state and keyboard focus are different concepts and must be visually distinguishable.
5. Brand Navy/Magenta are scarce emphasis resources.
6. Success/Warning/Error are semantic, not brand decoration.
7. Master-detail record selection is independent from bulk row selection.
8. Fake affordances are forbidden.
9. Data-heavy screens should expose controls near the data: saved views, search, filters, display settings and bulk actions.
10. When selection exists, batch actions appear in the table context.
11. Empty states explain the next useful action.
12. Destructive actions require confirmation when costly or irreversible.
13. Motion explains state but must not delay work; reduced-motion is supported.
14. Keyboard access and visible focus are acceptance requirements.
15. Do not invent new UI patterns inside feature screens when an approved shared pattern exists.
