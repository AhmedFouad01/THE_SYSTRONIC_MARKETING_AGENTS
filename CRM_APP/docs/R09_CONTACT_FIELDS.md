# R09 contact system properties
Contacts expose email, phone, company and job_title; leads expose email/phone from their linked contact. These are top-level scalar API adapters, separate from `properties` (custom storage). A field is null and `sensitive_masked` is true unless sensitive.read is allowed on the record and its contact. No presence hints or channel actions are available when masked. Session sensitive_read/write flags include assigned creation scope; record writes still enforce both row permissions.
Registry metadata has storage=protected and stable system_field. Existing custom keys/values stay unchanged: the seed chooses system_<field>, then numeric suffixes on collisions. Protected values stay outside custom storage; type/storage/flags remain immutable, while labels/group/position follow existing system-property editing. Defaults include all six object/field definitions.
POST/PATCH scalar email/phone reuses encrypted contact_identifier values and keyed lookup digests; historical values/provenance are preserved and the requested value becomes primary. Existing identifiers arrays and import targets remain supported. Company/job_title are encrypted nullable contact fields (300 characters); no plaintext custom/search copies are created.
Email is normalized to trimmed NFC lowercase; phone accepts E.164 or Egyptian local digits with default +20 (Arabic/Persian digits included); URL accepts only HTTP(S), no credentials/control/bidi characters. Registry email/phone/url types validate on server and client. Protected fields are excluded from search, sorting, filters and props=custom expansion. Visible normalized values enable mailto/tel/WhatsApp actions.
Migration 028 adds encrypted business columns, identifier primary metadata and protected registry definitions; existing record/identifier counts stay unchanged. Seed is repeatable and prior tenant seeds are wrapped. RLS remains forced and new guarded definers revoke PUBLIC execution. UI chrome remains EN/AR.

The existing fixed importer exposes email/phone; Company/Job title are entered through the contact create/edit panel and scalar API. `property:<key>` imports continue to address actual custom definitions only, including preserved colliding keys. They are never redirected to protected plaintext copies.
