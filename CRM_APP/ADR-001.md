Accepted for the synthetic M0 spike, 2026-10-01. No foundation comparison or production approval.

`package-lock.json` locks transitive packages. npm metadata licenses reviewed; `npm audit` observed zero reported vulnerabilities on 2026-10-01. This is not a commercial legal opinion or a guarantee against undisclosed vulnerabilities.

API and worker are separate processes sharing a database. No Redis: one bounded database effect needs no second queue. `FOR UPDATE SKIP LOCKED` holds the claim through the effect and acknowledgment transaction; process death releases the lock and rolls back the effect. Outbox remains recovery truth. External provider delivery is excluded; a future adapter needs its own stable destination/delivery key and reconciliation contract, never the expiring API key.

Opaque, randomly generated, SHA-256-hashed synthetic session tokens stand in for future identity-provider authentication. RLS validates the token against a protected session table and current membership/grant, rather than trusting tenant/actor settings alone. Settings are transaction-local on a checked-out connection. Runtime is non-owner, NOSUPERUSER/NOBYPASSRLS, has no authority administration privileges, and cannot mutate audit/history/event/command evidence. Small SECURITY DEFINER authorization functions use a fixed search path; only constrained wrappers are callable by runtime. Server object/action checks apply before replay; workers recheck the initiating actor and exact grant before each effect. This is an application/database trust boundary, not protection from a compromised runtime process holding valid users' tokens. No generic ACL engine or production identity/MFA claim.

The fixed M0 catalogue uses manager, assigned-only rep, reader, and worker roles. Agency grants are client-owned and restricted to one deal and one action; intersect with current agency membership/role. Seed/administration remains privileged offline tooling. Only stage/version are editable through the runtime API; unknown request fields are rejected.

Four lifecycles remain separate: seven-day API response lookup; durable command receipt plus transition/event business identity; outbox execution identity plus unique worker effect; future provider-delivery identity. Cache expiry never deletes a command/event/effect. Permanent synthetic receipt retention is not an approved production privacy-retention policy.

Minimal HTML/CSS/JavaScript is sufficient for this two-language proof; no frontend framework. `PrivateStorage` is an interface only. Tenant portability, attribution and conversion-truth decisions remain in the Blueprint; their products are outside M0.
