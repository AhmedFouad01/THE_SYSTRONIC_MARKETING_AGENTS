## 0. Principles
1. `colors.ts`/`scales.ts` stay the ONLY source of raw values (no-raw-colors test). Tailwind never gets its own palette: `@theme` maps utilities to `var(--sy-*)` references (`@theme inline`), so the existing `data-theme` switch keeps working and nothing is duplicated.
2. No Tailwind `dark:` palette utilities. Mode flips by redefining `--sy-*` (already done in css.ts). Only `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *))` is declared for the rare glass-only override.
3. Logical utilities only (`ps/pe/ms/me/start/end/text-start/border-s/rounded-s`, `inset-inline`). Banned in components: `left-* right-* ml-* mr-* pl-* pr-* text-left text-right rounded-l/r border-l/r` (extends UI_R4 s.I grep test; allowlist = preview dock `right-0`, scrollbars). Add Biome/grep rule in batch 0.
4. Direction-specific motion stays explicit per UI_R4 G; RTL is not a flipped EN.

## 1. Tokens -> Tailwind v4 theme (`app/src/ui/theme/tailwind.css`, generated from tokens by css.ts/script, not hand-edited)

```css
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));
@custom-variant rtl (&:where([dir="rtl"], [dir="rtl"] *));
@theme inline {
  --color-*: initial;                 /* kill default palette: only role colors exist */
  --color-canvas: var(--sy-canvas);  ...one line per token below...
  --font-body: var(--sy-font-body);  --font-heading: var(--sy-font-heading);  --font-data: var(--sy-font-data);
  --radius-6: var(--sy-radius-6); ... --radius-12: var(--sy-radius-12);  --radius-pill: 999px;

  --spacing: 1px;                      /* utilities p-12 = 12px, matching sy space names; allowed set = spacing.ts keys */
  --ease-out: var(--sy-ease-out); --ease-in: var(--sy-ease-in); --ease-std: var(--sy-ease-std);
  --breakpoint-*: initial; --breakpoint-sm: 480px; --breakpoint-md: 720px; --breakpoint-lg: 920px; --breakpoint-xl: 1180px;
}
```
Breakpoints: handoff gives max-width (compact 1180, stacked 920, mobile 720, small 480). Tailwind is min-width first, so define `@custom-variant max-xl (@media (max-width:1180px))` etc. (Tailwind v4 also ships `max-*` variants: `max-md:` = <=720 minus 1px; DEV verify off-by-one and keep `@media (max-width:720px)` parity via custom variants `mobile:`, `stacked:`, `compact:`, `small:`).
Color mapping (Tailwind name = kebab of token key; utility `bg-surface-2`, `text-text-2`, `border-border-strong`). Every existing key, both modes, via the same var:
- Surfaces: canvas, overlay, surface, surface-2, surface-3, raised, nav, hover, selected, disabled-bg.
- Lines: border, border-strong, divider.
- Text/icon: text, text-2, text-3, text-disabled, icon, icon-muted. (Utility `text-text-2` is awkward: ALSO expose aliases `fg`, `fg-2`, `fg-3`, `fg-disabled` pointing to the same vars for readability; the `--sy-*` names remain canonical.)
- Actions: primary, primary-fg, primary-hover, primary-pressed, create, create-fg, create-hover, create-pressed, interactive, focus, focus-ring.
- Status (bg/fg/icon triplets): info-*, success-*, warning-*, danger-* (+ danger-hover, danger-pressed, danger-field-bg).
- KPI: kpi-navy-bg/fg/sub, kpi-magenta-bg/fg/sub.
- Charts: chart-1..chart-8.
- Not in colors.ts but referenced by css/spec: `--sy-active` (UI_R4 E) and motion `--sy-dur-*`/`--sy-ease-*` (UI_R4 G): add to tokens first (batch 0), then map. NEW glass tokens (s.3) are added to `colors.ts`/`scales.ts`, never in CSS.
Typography AR+EN: Tailwind text sizes are role utilities that read the already-locale-switched vars, so AR (+1px, line 1.6) needs no `ar:` variant:
`@utility text-page-title {font:var(--sy-type-page-title-weight) var(--sy-type-page-title-size)/var(--sy-type-page-title-line) var(--sy-font-heading)}` and same for `text-section-title`, `text-body`, `text-data`. Use `font-body/heading/data`; never `font-sans`. `:root[lang=ar]` overrides already exist in css.ts. Numerics: `tabular-nums` + `.sy-ltr` islands (`@utility ltr-island {direction:ltr;unicode-bidi:isolate;text-align:start}`).
Focus: `@utility focus-ring {outline:var(--sy-focus-width) solid var(--sy-focus);outline-offset:var(--sy-focus-offset)}`; inputs use `-offset-input`. Applied via `focus-visible:focus-ring` (RAC sets `data-focus-visible`; plugin variant `focus-visible:` maps to it). Selected is NEVER the focus color (UX_RULES 4).
Sizes: `h-control` (36), `h-control-sm` (32), `min-h-row` (44) via `--spacing`-independent `@theme` keys `--height-control` etc.

## 3. Glass / transparency direction (additive)
Concept: frosted translucent surfaces for FLOATING/TRANSIENT layers that sit over content, using existing role colors with alpha. Content that is read or edited stays solid. Reference vocabulary: Apple "materials" (thin/regular/thick by use), restraint rule.
Where glass IS used (4 materials, nothing else):
| Material | Used on | bg (surface token @ alpha) | backdrop | border | shadow |
|---|---|---|---|---|---|
| `glass-menu` | Select/ComboBox/Menu/DatePicker popovers, command palette | `surface` @ 88% | `blur(14px) saturate(140%)` | 1px `border` @ 70% | `shadow-menu` |
| `glass-panel` | preview slide-over frame (header + footer chrome), bottom sheet grabber/header, Dialog frame | `raised` @ 90% | `blur(18px) saturate(140%)` | 1px `border` @ 70% (inline-start edge only on the preview panel: `border-s`) | `shadow-modal` |
| `glass-bar` | sticky page toolbar / table sticky toolbar when content scrolls under it (NOT table header), topbar on scroll, mobile bottom nav | `surface` @ 86% | `blur(12px) saturate(130%)` | bottom 1px `divider` | none (shadow only when scrolled) |
| `glass-scrim` | ModalOverlay only | existing `overlay` token + optional `blur(2px)` on desktop only | | | |
Sidebar: SOLID `nav` (always visible, long dwell, dense text, big area = perf cost). Optional later: none. Do not add glass to cards, KPI tiles (brand emphasis colors), tables, headers of grids, forms, record body, toasts, tooltips, buttons, badges, charts.
Preview panel: only its chrome (header 56 + sticky footer) is glass; the BODY (facts, notes, activity, forms) is solid `surface` so the long text/edit area has guaranteed contrast and avoids a full-height blur layer. Where body meets header, content scrolls under the glass header (the point of the effect).
Tokens to add (colors.ts, light/dark, no hex in CSS): `glassMenuBg`, `glassPanelBg`, `glassBarBg`, `glassBorder`, `glassHighlight` (1px inset top `rgba(255,255,255,.5)` light / `.06` dark, optional). Light bases: `rgba(255,255,255,.88/.90/.86)`; dark bases: `rgba(17,23,34,.88)` / `rgba(28,37,50,.90)` / `rgba(17,23,34,.86)` (surface/raised values with alpha, so they equal the opaque token + alpha). Scales: `--sy-blur-menu:14px`, `--sy-blur-panel:18px`, `--sy-blur-bar:12px`. Utilities: `@utility glass-menu {background:var(--sy-glass-menu-bg);-webkit-backdrop-filter:blur(var(--sy-blur-menu)) saturate(140%);backdrop-filter:...;border:1px solid var(--sy-glass-border)}` (+ panel, bar).
Contrast rules (computed, WCAG relative luminance; text over glass over WORST-CASE backdrop = full brand fill behind: navy `#181D36` light, white / cyan in dark):
| Pair | alpha | light worst | dark worst |
|---|---|---|---|
| text | .86-.92 | 12.5-14.1 (navy behind) | 11.3-13.7 (white behind) |
| text-2 | .86 / .90 | 5.8 / 6.3 | 7.2 / 8.3 |
| text-3 | .86 / .92 | 3.7 / 4.2 FAIL small text | 4.6 / 5.6 |
Rules: (1) alpha floor 86% anywhere text sits (never < .80: text-2 is 5.1 light/5.8 dark there, text-3 fails). (2) On glass use `text`, `text-2`, `icon` only; `text-3`/`icon-muted`/placeholder-on-glass allowed only on dark or when a `surface` @100% inner field is used: inputs inside glass popovers (combobox search) are solid `surface`. (3) Interactive/hover/selected rows on glass use the existing opaque `hover`/`selected` fills at 100% (so selected `#D8F4FA` + text 4.5+ is unchanged) and keep the focus ring (3:1 vs both). (4) Borders carrying meaning (inputs) never glass. (5) Status color triplets never on glass. (6) Re-verify pairs with a script (s.5) because backdrop is content-dependent; the blur averages detail so the worst case is a large saturated block, which only KPI tiles (navy/magenta) create.
Fallbacks:
- `@supports not ((backdrop-filter:blur(1px)) or (-webkit-backdrop-filter:blur(1px)))`: glass vars resolve to OPAQUE tokens (`--sy-glass-*-bg` = `surface`/`raised` alpha 1), blur removed.
- `@media (prefers-reduced-transparency: reduce)` (Chromium/Safari; Firefox ignores = unaffected) and a user setting `data-transparency="solid"` on `<html>` (Settings, persisted like theme): same opaque resolution + `backdrop-filter:none` + `border-color:border-strong`. Also on `forced-colors: active` (system colors, borders visible) and `prefers-contrast: more`.
- Glass classes also drop blur while an element animates in on low-power: see limits.
Performance limits: max 2 simultaneous glass layers in a viewport (e.g. preview chrome + one popover); popovers/menus blur radius <=14px and area <= 360x320; panel chrome area <= 480x120 each; never full-viewport blur except `glass-scrim` 2px desktop-only (off at <=720px and on `(hover:none)` touch devices); no nested backdrop-filters (a glass inside a glass = flatten inner to solid `surface`); no blur on scrolling lists items, table rows or sticky table headers; do not animate blur or alpha (animate transform/opacity only); `will-change` not set permanently. Budget check: panel open/close at 4x CPU throttle holds 60 fps on a 1000-row grid, otherwise ship `data-transparency="solid"` as default for that tier. No images/gradients behind glass are added: glass sits over existing solid `canvas`/`surface`, so the effect is subtle depth rather than decoration.
