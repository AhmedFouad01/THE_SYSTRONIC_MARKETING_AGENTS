## 2. AR conflict: overlay (spec default) vs reserve padding (fallback)
Geometry at 1440 AR (estimates): sidebar 228px at right; gutter 24; selectable checkbox column ~44px; identity column is the flex column (min 240, absorbs remaining width, ~400-470px). Panel = `clamp(360,32vw,480)` = 461px. So the panel covers: the whole sidebar, the gutter, the checkbox column and ~165px of the right (= START) part of the identity column. At 1920: page is capped 1440 and centred, so ~126px margin sits between sidebar and table; panel 480 covers ~126px less of the table, ~114px of identity visible further; the overlap is smaller. At 1181-1279 (panel 380) the covered part of identity is smaller in px but the identity column is also narrower (min 240).

| | Overlay (spec default) | Reserve `padding-inline-start:400px` while open (fallback) |
|---|---|---|
| What the AR user sees | Table does not move. The right 461px (sidebar, checkbox, the beginning/avatar of names) is under the panel; the rest of the row (status, owner, source...) stays visible and the selected row keeps a full-row tint. The name is repeated large in the panel header | Table shifts/narrows by 400px: 1164 -> ~764px. Container queries then hide `data-collapse` columns (<880) - the table visibly drops 1-2 columns and re-flows every time the panel opens/closes. Identity column fully visible. Sidebar still covered by the panel |
| EN counterpart | Panel covers the end columns (Source/Created) and the toolbar end; identity stays visible | EN would need the mirror reserve (padding-inline-end) - spec says reserve only in AR, so EN and AR would differ in layout behavior |
| Reflow / jump | None, motion is transform+opacity only | Layout shift of ~400px + column drop; animating padding is not allowed by the motion rule (only transform/opacity) so it would snap. This is exactly the "table squeezed" look the user rejected in screenshots |
| Looks like | HubSpot/Linear overlay drawer; premium, calm | Old split view again, just lighter |
| Weakness | Beginning of AR names, avatars and the row checkbox hidden while open; sidebar navigation unreachable until closed (outside click or Esc) | Table loses columns; two behaviors to test; extra state bugs (scroll anchor, selected row position) |

Recommendation: keep the OVERLAY as the default in both languages. Reasons: (1) it satisfies "table width unchanged" and the user's complaint (squeezed table) in both languages with one code path; (2) the covered portion is the least informative part once the row is open, because the panel header already shows the full name + avatar; (3) the reserve fallback reproduces the squeeze at 1440 (764px table, collapsed columns) which is the visible damage to avoid; (4) overlap shrinks at 1920 where most users with wide screens are.
Make three small additions so the AR overlay does not feel like a bug: (a) selected row gets a FULL-row `--sy-selected` tint in addition to the inline-start bar (the bar sits under the panel in AR); (b) on open, `scrollIntoView({block:'nearest'})` only (never horizontal); (c) panel is positioned below the topbar (`top:var(--sy-topbar-h)`, height `100dvh - 56px`) so the language/theme/user controls and breadcrumb remain reachable, and the sidebar brand stays visible in AR. Wire the fallback as a switch DEV can flip without a rebuild of markup: a CSS custom property `--sy-preview-reserve` (default 0) applied as `padding-inline-start` on the grid scroller when `[data-preview-open]`, and flip it only if the re-audit shows names unreadable at AR 1440. Decision point for the user: look at AR 1440 dark with a long Arabic name before approving.
Open question for the Lead (SK-026): should the panel also reserve the sidebar in AR instead of covering it (i.e. dock at the main-area right edge, not the viewport edge)? Cheaper and cleaner (nav stays usable, no overlap with the sidebar) but violates "docked to the physical right edge" literally; I recommend treating it as a visual option to show in the first screenshot, not as default.

## 4. Guard-rails: must stay unchanged (R4 B1 design that passed re-audits)
- Select list sizing/F1 behavior (min trigger width, ellipsis single line, no per-character wrap) and the "Source" filter alignment to trigger inline-start.
- F2 focus: no cyan wrapper ring on mouse click; ring only on `:focus-visible` rows/cells/buttons.
- Brand/crumb links, record route crumb (`RecordCrumb`, `useCrumbReturn`/`useRecordCrumb`), `CRM > Leads > name` return to the filtered list.
- Edit model: Save always visible and disabled until dirty, Cancel; no `RecordEmpty`-style resurrection of the old cancel bar; sticky footer behavior of `record-panel.css` (`.sy-record__footer` margins use negative inline margins: keep consistent with the new panel padding).
- No owner caption under the name; ID/Version hidden for non-admin (technical details closed).
- Page frame: topbar 56, gutters 24/16/12, `--sy-page-max:1440`, control heights 36/32, row height 44, grid sticky header.
- DataGrid contracts: single-line ellipsis cells, `data-collapse` container queries, bulk bar overlay of the toolbar slot, batch bar on phone, saved views, density, column set (6 default).
- Toolbar layout and `.sy-grid__count` position; mobile card list at 375; bottom nav 68px and its `z-index:60`.
- Dialog stack: Merge/Lost-reason/New* dialogs (scrim 1000) and toasts 1100 keep working over the panel.
- Tokens: no hard-coded px/colors beyond tokens; logical properties everywhere EXCEPT the explicit physical dock (allowlist the new panel rules in the CSS lint).
- Dashboard, Pipeline board, Journey, all forms: zero visual change.
- Test hooks: keep `data-testid` for record panels/sheets (`deal-detail`, `deal-sheet`, `report-detail`, contact/lead/task detail ids) or update the Playwright specs in the same change (tests `mvp-contacts|leads|tasks|deals|record-grid|bulk|ux-r2|ui-r4-b1` reference the detail pane and `autoSelectFirst`).
