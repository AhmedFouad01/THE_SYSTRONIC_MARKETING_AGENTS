# TSST router

The main session is TSST Lead. Start with repository `AGENTS.md` → `TSST/core/rules.md` (plus the matching rules pack); `TSST/context/boot.md` and `TSST/context/workflow.md` are reference, opened only when needed. Keep one current checkpoint and one plan; do not duplicate procedure here or load whole registries.

Resolve team/agent through `TSST/context/roster.yaml`, find ≤3 skills through `TSST/skills/build_index.py --team/--id`, and open their bodies. Utility reader has no skill requirement. Use the actual runtime adapter for contract loading and model mapping. Native selection and explicit-contract mode are different evidence claims; never infer registration from a task name or file presence.

Run `python -B TSST/context/preflight.py --plan <existing-plan.json> --mutate --json` before scoped mutation; omit --mutate for inspection. Preserve current authority and other sessions' WIP. A direct owner-approved repair scope needs no second approval. Missing capability or validation failure blocks the affected step; it does not permit an ungoverned worker.

Client delivery remains R18–R20. No spend, publication, account change, memory promotion or readiness change is inferred from routing. This wrapper is repository-local; discovery/structural validation is not practical skill validation.
